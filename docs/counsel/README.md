# Counsel instructions

One file per open legal gate, written so it can be handed to qualified counsel
without a conversation first. Each states what the project does today, what it
proposes to do, and the specific questions whose answers change the code.

**These are questionnaires, not legal advice, and not authorization.** Nothing
in this directory clears processing, publication or an external message. A
completed instruction becomes authority only when counsel has answered it and an
authorized human has recorded the decision — the decision record at the foot of
each file is where that goes, and until it is filled in the affected work stays
on hold.

They are drafted in the open for the same reason the rest of the repository is:
a reader deciding whether to trust the output can see which questions the
project knows it has not answered. Detailed advice, holdings inventories and
anything naming a real entity stay out of here and in whatever channel counsel
asks for; these files carry the question and the published counts behind it.

The format follows the gate templates in
[`docs/automation/handoffs.md`](../automation/handoffs.md).

## No recipient is identified, and that is the blocker

"Drafted, not sent" below does not mean an instruction is queued behind
someone's reply. **No counsel is engaged, and none is named anywhere in this
repository.** The escalation list in the project's legal guardrails says to stop
and get qualified counsel; it does not say who that is, and nobody has been
found yet.

That is worth stating plainly because the drafting is the visible work and it is
done. Finding someone qualified to answer these — GDPR as it applies to a
privately held procurement corpus, under Swedish jurisdiction — is the step that
is actually outstanding, and it blocks more of this project than any engineering
item does. Open work
[#3](../open-work.md#3-document-and-drop-the-fields-that-can-name-a-natural-person),
[#14](../open-work.md#14-decide-what-to-do-about-personal-data-in-fields-that-are-not-contact-fields),
[#17](../open-work.md#17-build-the-first-classifier) and
[#18](../open-work.md#18-validate-correction-handling-against-a-continuous-archive)
all wait behind the processing half of #11.

Nothing here proposes what to do about current holdings in the meantime. That
question is open and undecided.
