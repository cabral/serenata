# ADR-0001: Local-first, data outside the repository

Status: accepted, 2026-09-10

## Context

The pipeline processes personal data about elected officials and company officers. The code is public so anyone can inspect and rerun it. The data and the results are not published: the maintainer runs the pipeline on his own machine in Sweden and shows case packets to journalists and research partners.

Under Sweden's dataskyddslagen (1 kap. 7 §), GDPR articles 5 to 30 and 35 to 50 do not apply to processing for journalistic purposes or for academic, artistic or literary creation. The security obligations still apply.

A public repository is the most likely place for personal data to leak by accident: a fixture copied from a real record, a committed Parquet file, a screenshot pasted into an issue, a notebook with its outputs saved. Agent sessions are a second path, because anything a session prints ends up in a transcript.

## Decision

- All downloaded and derived data lives under `$CRONY_DATA_DIR`, an absolute path outside the repository, on an encrypted volume. `config.py` refuses any path inside the repository, including through symlinks.
- The repository contains code, docs, and fixtures generated by Python builders. Static data files are blocked by `crony-eu/scripts/check_no_data.py`, which runs as a pre-commit hook and in CI.
- Agent sessions inspect real data only through schemas, counts and pattern summaries (CLAUDE.md, constraint 11). The maintainer looks at real records himself, in `crony review`.
- There is no hosted service. The HTML output is a single file that makes no network requests.
- Sharing a case packet is a manual act by the maintainer.

## Consequences

- No shared server, so no multi-user review. OpenAleph stays out until several people need to work on the same data.
- Anyone who clones the repository starts with no data and downloads the sources themselves.
- Reproducibility comes from the raw snapshots and their manifests, which stay on the maintainer's disk.
- The data guard will block the occasional legitimate file (a JSON editor setting, say). Those get an explicit allowlist entry in the script, reviewed like any other code change.

## Amendment, 2026-09-16: local is not the same as private

Two sentences in this record were read as privacy guarantees and are not.

**"The maintainer runs the pipeline on his own machine" is a statement about who processes, not about what is disclosed.** A case packet shown to a journalist has left the machine as completely as a website would have. Local operation removes a hosting surface and a hosting provider; it removes nothing from the packet. The export rules that decide what a packet may contain are CLAUDE.md constraint 11, and they exist because this record does not cover that question.

**The journalistic exemption in dataskyddslagen 1 kap. 7 § is an argument, not a ruling.** It disapplies GDPR articles 5 to 30 and 35 to 50 for processing carried out for journalistic purposes. Whether a given piece of this project's processing is for journalistic purposes is a question someone else decides, after the fact, on the facts. Building as though it definitely applies and building as though it definitely does not are both wrong; the security obligations apply either way, and the ones this record already names (an encrypted volume, data outside the repository) are the floor rather than the answer.

A third thing this record did not say: **an aggregate is not automatically person-free.** A share computed over a commune of four hundred people with one supplier names a person to anyone who lives there. CLAUDE.md constraint 12 sets the rule; the original text's implication that aggregate counts are always safe to write down was too broad.

None of this changes the decision. It changes what the decision may be cited for.
